# rust-l4: CPU-квоты доменов (v0.10 → v0.13)

CPU-квота — rlimit-атрибут песочницы GTCB: предел потребления
процессора доменом за период. Реализация прошла два поколения: v0.10
ввела троттлинг доменов с тиковой точностью, v0.13 перевела учёт на
циклы TSC и вытеснение на LAPIC TSC-deadline — суб-тиковая точность в
обе стороны и перебор квоты в МОМЕНТ исчерпания.

## 1. Модель

`TaskLimits::cpu_quota` — максимум тиков планировщика за период
(`usize::MAX` = без лимита; трещотка распространена и на неё:
расширить чужую/свою квоту через TASK_SET_LIMITS нельзя — только
ужесточить). Троттлинг — парковка ПОТОКОВ домена в отдельный список
до границы периода: домен за пределом квоты не диспетчеризируется,
бюджет возобновляется на границе.

Период — политика бекенда x86_64 (семантика v0.10, сохранена в
v0.13): `CPU_PERIOD_TICKS = 100` ГЛОБАЛЬНЫХ суммарных тиков всех CPU,
т.е. wall-время периода = `CPU_PERIOD_TICKS / (ncpu × SCHED_HZ)` с
(при SCHED_HZ=100: 0.5 с на двух CPU, 0.25 с на четырёх). Суммарная
семантика выбрана для fairness: домен с квотой K получает K/100
машинного времени regardless от числа CPU.

## 2. Заряд: циклы TSC (v0.13)

Единица учёта — **циклы TSC**; публичная семантика (квота в тиках)
не изменилась: тик = `TcbManager::set_cpu_time_unit(lapic::
tsc_per_tick())` циклов (бенд задаёт калибровкой PIT→TSC до старта
SMP; дефолт 1 — host-тесты и платформы без TSC). Сравнение с квотой —
`quota × unit` циклов.

Отрезок исполнения потока — от диспетчеризации до парковки:
метка `rdtsc` пишется в per-CPU GS-поле `OFF_DISPATCH_TSC` (протокол
per-CPU — только дописывание в конец), заряд = `rdtsc(парк) −
rdtsc(диспетчеризация)`. Заряд происходит на КАЖДОМ конце отрезка:

- **вытеснение**: квант RR, yield (THREAD_YIELD), resched-IPI;
- **блокировка**: IPC send/recv/call/recv_any, DEVICE_CLAIM.

Ядровые участки потока (сисколы, фолты) входят в отрезок честно —
между диспетчеризацией и парковкой TSC идёт непрерывно.

**Анти-спин-пол**: заряд отрезка не ниже
`max(tsc_unit, MIN_CHARGE_CYCLES=1024)` циклов — болтливый IPC-DoS
(«вычислить-и-заблокироваться» каждые микросекунды) не дешевле
честного кванта. Длинные отрезки точны в обе стороны: v0.10 грубил
(2.4 тика исполнения = 2 тика заряда), v0.13 заряжает 2.4 тика —
аудит печатает честные `charged 96007605 cycles` против квоты
3 тика (≈3.84 — перерасход одного пробуждения, см. §7).

`TaskUsage::cpu_used` (тики) — floor-производное от
`cpu_used_cycles` (кламп в квоту) — для аудита и exit-payload.

## 3. Период и его граница

Граница периода — ГЛОБАЛЬНАЯ TSC-граница `PERIOD_END` (атомик):
wall-семантика v0.10 (100 суммарных тиков всех CPU), но граница
ТОЧНАЯ по TSC, а не «на ближайшем тике». Закрытие периода — CAS:
один победитель выполняет refill (сброс учёта всех доменов),
дренаж троттл-листа в готовность, sweep мёртвых контекстов,
рассылку resched-IPI. Проигравшие CAS не дублируют работу.

Проверка границы — lock-free peek (`rdtsc` против Acquire-чтения
`PERIOD_END`) на preempt-шаге; тиковый счётчик v0.10
(CPU_TICKS/CPU_PERIOD_WRAP) удалён. Idle-будка взводит one-shot
TSC-deadline точно на границу — троттл-лист возвращается в
готовность в срок, даже если нет ни одного работающего домена.

## 4. Троттлинг

Домен за пределом квоты помечается (`cpu_throttled` — зеркало
решения `charge_cpu`; каждое повторное включение — +1
`cpu_throttle_events`). Потоки такого домена при ВЫТЕСНЕНИИ паркуются
в троттл-лист (state Ready БЕЗ очереди готовности — до границы
периода): `KernelGlue::throttle_thread` → `TcbManager::
thread_park_throttled`. Смерть/суспенд потока вычищает и его —
погашенный поток не зависает в троттле (`deschedule` Dead/Suspended
дренирует список).

Парковка происходит на preempt-шаге гейта (`sched::preempt_step` —
единый шаг по тику И по выходу из сискола): refill периода → заряд
домену через glue (`on_timeslice_consumed`) → rotate ИЛИ троттл-парк.
Выход «единственный поток — вытеснение бессмысленно» удалён ещё в
v0.10: одиночный спиннер-DoS честно парковался бы квотой.

## 5. Вытеснение TSC-deadline

LAPIC-таймер в режиме TSC-deadline (CPUID.01H:ECX[24]; MSR
`IA32_TSC_DEADLINE` 0x6E0; LVT bit18): запись ненулевого значения
взводит one-shot, ноль — гасит. Каждая диспетчеризация взводит
one-shot на

```
min(RR-квант,                       # SCHED_HZ/10 тиков ≈ 100 мс
    остаток бюджета домена,         # до исчерпания cpu_quota
    остаток периода)                # до PERIOD_END
```

— домен перебирает квоту В МОМЕНТ исчерпания, а не «до ближайшего
тика». Перевзвод из ядра (`!from_user`-участки: сисколы без выхода в
пользователя) — эпсилоном: ядровые секции короткие, отложенный
вытеснение дешевле перевзвода на каждом входе.

Фолбэк без CPUID-фичи — прежний периодический тик (квант в GS):
заряд циклами и TSC-граница периода работают в ОБОИХ режимах.
Диагностика старта: `kmain: timer mode: tsc-deadline | periodic
fallback`. **QEMU/TCG вырезает tsc-deadline (не эмулирует)** — в
эмуляторе живёт фолбэк; дедлайн-путь — KVM/железо.

## 6. ABI

Все расширения обратно совместимы (v0.6-ABI не менялся):

| Место | Слова |
|-------|-------|
| TASK_SET_LIMITS (0x1D) | `arg5[63:16] = cpu_quota`; 0 — «не трогать» (наследие v0.9 — старые вызовы не замораживают домен), все единицы — «без лимита» (трещотка не ослабит), 1.. — квота в тиках за период |
| TASK_LIMITS_INFO (0x1E) | слово 6 = cpu_quota (`usize::MAX` = без лимита), 7 = cpu_used (тики текущего периода), 8 = `cpu_throttle_events \| (cpu_throttled ? 1<<32 : 0)` |
| TASK_SPAWN_IMAGE (0x1F) | дескриптор `u32 @ 0x6C` = квота ребёнка: 0 = без лимита (паддинг v0.9), `0xFFFF_FFFF` = явно, 1..=0xFFFF_FFFE = квота; применяется ДО первого потока — «окно без квоты» невозможно |
| ExitPayload::Exit | w4 = cpu_used, w5 = cpu_throttle_events — вердикт у родителя БЕЗ гонок с reaper'ом (TASK_LIMITS_INFO мёртвого домена — NotFound) |

Ядро-контракт (host-тесты): `set_cpu_time_unit`, `charge_cpu_cycles`,
`cpu_budget_cycles_left`; тест субтик-точности — квота 3 тика = 30
циклов при unit=10: граница ровно на исчерпании.

## 7. Гранулярность и открытые пункты

**Документированное окно перерасхода**: пробуждённый IPC-поток домена
за пределом квоты отрабатывает ДО ОДНОГО вытеснения — перерасход
ограничен (≈ живые_потоки × квант на границу периода; в демо ≈3.84
тика против квоты 3). Синхронные спиннеры паркуются немедленно при
каждом вытеснении. Закрытие окна — enqueue-проверка квоты
пробуждённых IPC (открытый пункт): планировщик проверял бы бюджет
домена в момент enqueue, а не только на preempt-шаге.

Открытые пункты (roadmap):

- enqueue-проверка квоты IPC-пробуждений (закрытие окна перерасхода);
- частичный unmap IOMMU с расщеплением huge-листа (ортогонален квотам,
  открыт с v0.8);
- per-CPU очереди готовности (сейчас — одно lock-free MPMC-кольцо
  глобальной готовности; масштабирование CPU>4 — предмет будущих
  версий).

Аудит-картина живого прогона (QEMU, квота rogue = 3 тика):

```
[kernel: sandbox] cpu quota: domain 0194... throttled
                 (charged 96007605 cycles, limit 3 ticks per period)
...
[init] exit payload: code=0x5A cpu_used=3 throttle_events=1
[init] cpu quota HELD
```
