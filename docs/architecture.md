## 1. Слои и контракты

Проект делится на крейты по принципу «политика отдельно от механики».
Зависимости направлены строго вниз; горизонтальных связей между
платформенными крейтами нет.

| Слой | Крейт | Ответственность |
|------|-------|-----------------|
| Загрузка | `uefi_stub`, `boot_info`, `bootcfg` | UEFI-заглушка (образ ядра встроен), BootInfo-ABI, разбор boot_cfg.xml |
| Механика ISA | `arch` (+ крейт `x86_64`) | per-CPU блоки через GS, COM1 16550, константы загрузочного ABI, MSR |
| **Контракты HAL (v0.15)** | **`kernel-hal`** | типы (PhysAddr, Bdf, DevicePath) + трейты платформы; НЕ зависит ни от одного крейта workspace — экспозиция архитектуры не проникает между крейтами (граница видна cargo) |
| Ядро | `kernel` (`pkg_generic_interface`) | GCTL — фасад менеджеров; реэкспорт контрактов kernel-hal + IrqRouter (механизм GSI→endpoint); syscall-таблица; sync-примитивы |
| Исполнитель x86_64 | `backend` | гейт входов, планировщик, LAPIC/IOAPIC, SMP/IPI, память (MMAP/KMAP/ASID), VT-d/AMD-Vi; реализует контракты kernel-hal — единственное место экспозиции архитектуры |
| Политика запуска | `startup` | kinit: порядок инициализации, elfload, пулы, KernelGlue |
| Пользователь | `init`, `rogue`, `userlib`, `pie` | серверы, C-ABI-обёртки, PIE-загрузчик спавна |

**GCTL** (`kernel/src/lib.rs`) — корневой фасад, владелец менеджеров:
`TcbManager` (домены + потоки), `CapabilityManager` (cspace,
гейты, деривация/отзыв), `MemoryManager` (физпул + фасады адресных
пространств + привязки задача→фасад), `IpcManager`, `ShmManager`,
`IrqRouter` (внешние линии GSI), `SyscallRegistry`. Реестра устройств
в GCTL НЕТ с v0.14 — ядро не знает ни одного устройства. Менеджеры
связаны между собой **параметрами, не полями** (паттерн
`CapabilityManager::ops(&TcbManager)`): GCTL — витрина, а не god-object.

**HAL-контракты** (`kernel-hal` — отдельный крейт с v0.15; ядро
реэкспортирует их как `kernel::hal::{types, traits}`): `MMAPInterface`
(адресные пространства пользователя), `KMAPInterface` (изображение
ядра, изоляция Meltdown/KPTI), `ASIDInterface` (PCID/ASID, FlushMode),
`DmaOps`/`DmaPlatform`, `ANIOMMUInterface` (агностик IOMMU),
`IrqLineOps` (внешние линии), `IoPortOps` (медитация I/O-портов — v0.14),
`CpuInterface`. Контрактный слой собирается автономно
(`cargo build -p kernel-hal`) — если перестал, архитектура начала
протекать. Перенос на другую ISA = реализация `Platform` (+ head.S +
гейт) в новом бекенде; политика kinit не меняется.

**KernelGlue** (`startup`) — интеграционная плоскость «арх-гейт ↔
ядро»: диспетчеризация сисколов, активация пространств, смерть/фолты
потоков. Реализация моно-морфизирована над GCTL; бекенд зовёт её через
глобальную установку.

## 2. Загрузочная цепочка

```
OVMF (pflash)
  -> ESP (MBR + FAT): /EFI/BOOT/BOOTX64.EFI, init, capp, boot_cfg.xml
     BOOTX64.EFI = uefi_stub (x86_64-unknown-uefi, kernel.bin ВСТРОЕН)
  1. mini-UART COM1 (единый канал отладки со стартом ядра)
  2. boot_cfg.xml: cmdline ядра, список серверов (<server>, <arg>),
     boot_state (транзитом в argv init)
  3. образы серверов читаются с ESP в память (модули BootInfo)
  4. сегменты ядра размещаются ДИНАМИЧЕСКИ: любой 2 МиБ-выровненный
     адрес в [16 MiB .. 4 GiB) — внизу OVMF держит декомпрессированный
     DXE-том; аналог Linux EFI stub
  5. BootInfo-страница: память (финальная карта после ExitBootServices),
     модули, RSDP (ACPI2 из configuration tables), cmdline
  6. ExitBootServices; RDI = &BootInfo (физика); прыжок на вход ядра
  -> head.S (identity по физике): строит PML4: high-half
     KERNEL_LINK_BASE = 0xFFFF_FFFF_8100_0000 -> фактическая физика
     (2 МиБ-страницы) + physmap 4 GiB @ 0xFFFF_8000_0000_0000;
     переключает CR3, прыгает в high-half
  -> kmain (backend/bin/kernel.rs): консоль, CPUID-детекты (RDCL_NO,
     TSC-deadline), MADT, LAPIC + калибровка TSC (PIT), SMP bring-up
     (APы паркуются до конца kinit), VT-d/AMD-Vi init (ДО release_aps)
  -> startup::kinit (арх-НЕЗАВИСИМАЯ политика):
     BootInfo.validate -> 2 x LLFree (ядро: AllocAll, пользователь:
     избирательное освобождение Available) -> куча (talc) -> slab-пул
     -> GCTL -> DebugSink/TimeSource/планировщик -> KMAP (изоляция,
     регионы ядра) -> elfload init (xmas-elf, map_fixed по PT_LOAD)
     -> стек USER_STACK_TOP + argv-блок (boot_state транзитом)
     -> задача/поток init -> стартовое IPC [argc, argv_ptr, argv_bytes]
  -> X86Platform::run(): release_aps -> контекстный цикл диспетчеризации
```

Ключевые инварианты цепочки: после ExitBootServices заглушка не
аллоцирует (RAII-владение забыто намеренно); ядро исполняется только по
high-half адресам, физика доступна через physmap; первый сервер
(модуль [0]) — init по договорённости протокола, его стартует ядро.

`meltdown=allow` в cmdline — Escape- hatch для QEMU/TCG (нет
`ARCH_CAPABILITIES.RDCL_NO`); без флага на железе без закрытого
Meltdown ядро отказывается грузиться (изоляция KPTI не включена —
честный отказ вместо молчаливой уязвимости).

## 3. Память

Физический уровень — два независимых пула **LLfree** (lock-free
аллокатор кадров, классы-размеры): ядро поднимается на `AllocAll`
(вся память ниже — занята), пользовательский пул избирательно
освобождает `Available`-регионы карты. Единица — страница 4 КиБ;
крупные запросы (таблицы IOMMU, Device Table 2 МиБ) идут через классы
порядков (order-9 и т.п.), детерминированно contiguous.

Над кадрами — три уровня владения:

- **Куча ядра** — `talc` (глобальный аллокатор slab-хуков ядра);
  slab-пул обслуживает GCTL-объекты (TCB, capability, дескрипторы).
- **KMAP** — изображение ядра + physmap + изоляция: контракт
  `KMAPInterface` (режимы изоляции Meltdown, MapFullKernel для
  переноса ядра между таблицами KPTI/PCID). Регионы ядра —
  supervisor RW NX.
- **MMAP-фасады** — адресные пространства задач: фасад `UFacade`
  на窗口 `USER_ALLOC_BASE = 0x0000_1000_0000_0000` (16 ТиБ),
  стека `USER_STACK_TOP = USER_ALLOC_BASE − 16 МиБ`. Менеджер памяти
  держит привязки задача→фасад (MemRouter для сисколов/IPC); смерть
  домена дропает фасад: owned-кадры возвращаются пулу, external-окна
  (стейджинг родителя при спавне) остаются источнику — L4 pager-модель.

Рантайм-пространства (v0.9): `SpaceFactory` — тип-стёртый сервис
`create_space/destroy_space` поверх геометрии платформы; спавн и смерть
домена пользуются только им. TLB-shootdown — единственный лок, под
которым ядро ждёт cross-CPU (битмап-ACK по IPI 0x22); waiter'ы всегда
на глубине 0, поэтому спин идёт с IF=1 и ACK доезжает.

Flexpage-модель: `MEM_TRANSFER`/IPC map-элементы отображают ОКНА
источника в пространство получателя (zero-copy, кадры остаются у
владельца до MEM_FREE) — так работает и спавн по готовому образу
(`MEM_MAP_AT`, право TaskTCB на получателя, зарядка квоты цели).

## 4. SMP

Топология — из MADT (RSDP → XSDT/RSDT → APIC): слоты CPU не уплотняются,
`cpu_id` = индекс всех per-CPU массивов. Bring-up: INIT-SIPI-SIPI на
AP, real→protected→long трамплин на фиксированной физике 0x8000,
почтовый ящик 0x8F00+ (GDT-дескриптор, long-entry, per-CPU указатель,
стек 16 КиБ, CR3, MAGIC 0xC0FFEE01 — BSP поллит готовность). Каждый AP:
свой GDT/TSS/IDT, MSRs, LAPIC, GS-блок per-CPU состояния.

Векторы прерываний (IDT/LAPIC):

| Вектор | Назначение |
|--------|------------|
| 0x20 | LAPIC-таймер (периодический тик планировщика; в TSC-deadline режиме — не взводится) |
| 0x21 | resched-IPI: цель ставит NEED_RESCHED в свой GS (чистый asm-обработчик) |
| 0x22 | TLB shootdown: инвалидирует локальный TLB, ACK по битмапу |
| 0x23 | halt-IPI паники: все CPU замирают cli+hlt |
| 0x40..0x57 | внешние линии IOAPIC (24 GSI q35, свой asm-стаб на линию) |
| 0xFF | spurious LAPIC |

Синхронизация времени: калибровка TSC по PIT (1193182 Гц) до старта
SMP; `lapic::tsc_per_tick()` — единица учёта квот (циклов на тик).

Известная особенность стенда: QEMU 10.x с MTTCG ненадёжно доставляет
IPI остановленному vCPU — `run_qemu.sh` запускает
`-accel tcg,thread=single`; на KVM/железе проблемы нет.

## 5. Модель синхронизации (v0.12)

До v0.12 все входы в ядро сериализовал один AtomicBool (Big Kernel
Lock) — контракт однопоточности ядра-крейта (RefCell-менеджеры). v0.12
демонтировал BKL полностью: каждая подсистема — собственный короткий
лок, горячие пути — атомики/lock-free.

Примитивы (`kernel/src/sync.rs`):

- **`KSpin<T>`** — спин-мьютекс с RAII и depth-хуками;
- **`KRwLock<T>`** — для read-снапшотов против write-мутаций
  (TcbManager: транзакции IPC-парковки — одной write-секцией
  [переход + публикация]);
- **`RawGate`** — статическая таблица пер-гейт локов
  `GATE_LOCKS[256]` (ёмкость cspace 16×16; нет проблемы времени
  жизни) — критсекции rendezvous по endpoint'у;
- **`MpmcQueue`** — lock-free кольцо Вьюкова: без аллокаций на пути,
  без ABA, без реаллокаций; ёмкость 1024 ≥ квота 512 потоков;
  очередь готовности планировщика.

**IF-дисциплина**: держатель любого ядрового лока всегда исполняется с
IF=0 (входы в ядро гасят IF); спин-ожидание на глубине 0 идёт с IF=1 —
ожидающий доставляет IPI (shootdown-ACK держателю KMEM); вложенное
ожидание — IF=0. Внешние прерывания физически не могут прервать
держателя → самодедлок IRQ-хендлера невозможен by construction.
Глубина захвата — per-CPU (GS); хуки wait/wake/depth ставит бекенд до
старта SMP; host-тесты живут на no-op-хуках.

**Ранги захвата** (дедлок-дисциплина):

```
GATE  (per-endpoint RawGate) ──▶ { TCB, SCHED, CAP }
CLAIM (DeviceClaimRegistry)  ──▶ { TCB, SCHED }
TCB   (TcbManager, KRwLock)  ──▶ SCHED (хуки enqueue/deschedule)
SCHED (контексты/block-очереди; готовность — lock-free)
CAP / KMEM / SHM / IrqRouter / SyscallRegistry — ЛИСТЬЯ
```

GATE→GATE запрещён (фазы `ipc_call` покидают лок до повторного входа);
GATE→KMEM запрещён (доставка map-элементов IPC — вне гейт-лока) —
ABBA-пары встречных вызовов устранены по построению.

Fine-grained владельцы: `TcbManager` — KRwLock; `CapabilityManager` —
KSpin + пер-гейт RawGate; `MemoryManager` — ops-лок (сериализует
`with_facade`: параллельный `&mut UFacade` двух потоков одного домена
невозможен); `ShmManager`, `DeviceClaimRegistry` (парк ждущих claim
под CLAIM-локом — lost-wakeup закрыт), `IrqRouter`, `SyscallRegistry`,
`IpcManager` (счётчики — атомики); IOMMU-агрегатор — ops-лок.

## 6. Планировщик (v0.13)

Единица планирования — **поток** (L4); легаси task-level enqueue
демонтирован (v0.13): `TcbManager::create/set_state` не уведомляют
планировщик, домены в очереди готовности не адресуются — записи-призраки
UUID (шум stale, пустые resched-IPI на каждый спавн) исчезли по
построению.

**Готовность** — lock-free MPMC-кольцо: enqueue из хуков TCB (под
write-гардом менеджера — кольцо локов не берёт, инверсий рангов нет),
pick — из диспетчеризации без чужих локов. **Deschedule ленивый**:
запись остаётся в кольце, pick отсеивает по ФАКТИЧЕСКОМУ состоянию TCB
(Dead-каскад «kill в момент rotate» отсеется, воскрешения нет).
Финальная защита — `mark_running` (Ready→Running под write-гардом):
провал = мимо, берётся следующий.

**Контексты** — per-CPU кэш (v0.13):

- Горячий путь (сискол-вход): контекст текущего потока пишется в
  per-CPU СЛОТ — без локов и аллокаций (боксы рециклируются per-CPU
  пулом на 4). Обычный сискол без блока/вытеснения не трогает
  глобальное состояние вообще (v0.12 брал KSpin и вставлял в BTreeMap
  на КАЖДЫЙ сискол).
- Парки (IPC-block, suspend, preempt-rotate, троттл): контекст
  экспортируется слот → глобальная карта ДО фиксации перехода
  (хуки стреляют на CPU-владельце под write-гардом). Инвариант:
  Ready/Blocked ⇒ контекст в карте; Running ⇒ в слоте (ровно одно
  место, дублей нет).
- Pick: контекст ИЗЫМАЕТСЯ из карты (zero-copy передача между CPU;
  v0.12 клонировал 680 Б и держал копию). Вошедший бокс помечается
  inflight и рециклируется на следующей диспетчеризации этого CPU —
  демонтаж Box::leak (утечка ~700 Б на переключение).
- Отказ публикации (поток убит в окне вытеснения) — `release_slot_if`;
  мёртвые парки ядровых kill-путей подметает `sweep_dead_contexts`
  на границе периода.

SAFETY-контракт: свой элемент кэша трогает только владелец CPU;
возвращающиеся прерывания (тип !from_user, irq_c, IPI-флаг) кэш не
трогают; невозвращающиеся пути (вытеснение/фолт/смерть)
взаимоисключительны по потоку управления.

**Вытеснение**: каждая диспетчеризация взводит one-shot LAPIC
**TSC-deadline** (CPUID.01H:ECX[24], MSR 0x6E0) на
`min(RR-квант, остаток бюджета домена, остаток периода)` — домен
перебирает квоту В МОМЕНТ исчерпания, а не «до ближайшего тика».
Перевзвод из ядра (!from_user) — эпсилоном (ядровые секции короткие).
Фолбэк без CPUID-фичи — периодический тик (квант в GS): заряд циклами
и TSC-граница периода работают в обоих режимах. Диагностика старта:
`kmain: timer mode: tsc-deadline | periodic fallback`. QEMU/TCG
tsc-deadline не эмулирует — дедлайн-путь живёт на KVM/железе.

**Троттлинг доменов** — см. [cpu-quotas.md](cpu-quotas.md): период —
глобальная TSC-граница `PERIOD_END`, закрытие одним CAS-победителем
(refill доменов + дренаж троттл-листа + sweep мёртвых + resched-IPI);
idle-будка взводит one-shot точно на границу.

## 7. Путь системного вызова

ABI x86_64: `rax` = номер, аргументы `rdi, rsi, rdx, r10, r8, r9`,
возврат `rax`. Вход — `syscall` (MSR STAR/LSTAR/FMASK), asm-часть
`ctxswitch` выравнивает стек (якорь rbx + and rsp,-16), rust-часть —
`gate::syscall_c`:

1. Сохранение контекста в per-CPU слот (v0.13; безусловно ДО
   диспетчера — повторное сохранение на блок-пути затёрло бы контекст
   следующего парка, баг-класс v0.12 закрыт).
2. IF-дисциплина: вход в ядро с IF=0, лочи не меняют флаг.
3. Диспетчеризация: `SyscallFacade::dispatch[_number]` — прямой
   индекс в плоской таблице слотов (256, аналог IDT; ноль аллокаций,
   O(1)). Хендлеры — stateless-объекты, право проверяется
   capability-слоем.
4. Блокируемые сисколы (IPC send/recv/call/recv_any, DEVICE_CLAIM):
   хендлер ставит per-CPU защёлку `syscall::record_block_latch` и
   паркуют поток (состояние → Blocked); гейт решает по данным СВОЕГО
   CPU (check-then-act-гонка «двойной запуск после разбуждения»
   закрыта: уже-разбуженный фрейм честно бросается).
5. Preempt-шаг на выходе (тиком или после сискола): заряд домену
   циклами (`on_timeslice_consumed`), refill периода, rotate либо
   троттл-парк; контекст сохранён ДО публикации готовности.

Фолты и паники рантайма пользователя: fault-обработчик собирает
снимок регистров → `TASK_EXIT_EXCEPTION` → ExitPayload::Exception на
exit-endpoint домена → каскад смерти. Ядровые паники: halt-IPI всем
CPU, `KERNEL FAULT` в консоль.

## 8. IPC и SHM

Endpoint'ы — Gate-capability. Ёмкость 0 — строгий rendezvous L4
(встреча отправителя и получателя), >0 — notification-канал с буфером.
`ipc_call` — отправка + ожидание на reply-endpoint без возврата в
пользователя; fast-path `IPC_SEND_THREAD` — прямая доставка потоку по
глобальному ThreadId (open-receive мгновенно, иначе очередь потока);
`IPC_RECV_ANY` — открытый приём. Сообщение: до N inline-слов +
flexpage-элементы (map/grant); слова читаются сквозной индексацией
`IPC_MSG_WORD`.

Rendezvous (v0.12) — пер-гейт критсекции `RawGate(gate)`:

- send: [claim ждущего получателя / буфер / парк отправителя] — одна
  секция; доставка map-элементов — ВНЕ лока (KMEM — лист);
- recv: [буфер → refill из send_q / claim отправителя] — секция;
  завершение фазы call (`complete_sender`) — вне лока (GATE→GATE
  запрещён — ABBA встречных ipc_call невозможен);
- «заблокирован?» решается per-CPU защёлкой, не повторным чтением TCB.

SHM/io_uring: регионы из физпула, SQ/CQ-кольца (геометрия
`SHM_SETUP_RING`), doorbell-endpoint (`RING_DOORBELL` — signal после
submit), отображение в оба домена zero-copy. Все операции — только
владельцу региона (owner-гейт, v0.9).

## 9. Сырые ресурсы и прерывания (v0.14: устройств в ядре нет)

v0.14 переводит ядро на модель seL4: **ядро не перечисляет и не знает
устройств**. Прежний `DeviceManager` (реестр, rescan, claims,
DeviceReference-capability, шины PCI/ACPI/ISA) и AML-интерпретатор
(крейт `acpi`) удалены из ядра целиком: перечисление — политика
юзерспейса (acpid читает ACPI/AML, будущий pcid обойдёт PCI config
через порты). Ядро осталось **механизмом**: медитация сырых диапазонов
за capability + доставка линий прерываний как L4-сообщений.

**IoResource-capability** — право на ДИАПАЗОН, а не на «устройство»:
`Mmio { base, len }` (физика; таблицы прошивки, MMIO-баре),
`IoPort { base, len }` (порты x86), `Irq { base, count }` (линии GSI).
Стартовый грант kinit (модель root task seL4): init получает физику
0..4 GiB + порты 0..64 KiB + линии 0..256, плюс факт `rsdp=0x…` в
boot_state (ссылка на таблицы; интерпретация — юзерспейс). Производные
— CAP_MINT (копия диапазона; сужение поддиапазона — roadmap).

**Сисколы группы 0x40** (все — только за IoResource-cap):

- `MMIO_MAP` (0x41): физика → байто-точный vaddr (кадры внешние,
  снятие MEM_FREE);
- `IOP_IN/IOP_OUT` (0x42/0x43): in/out исполняет ЯДРО (IOPL
  пользовательских контекстов = 0 — прямого доступа к портам из
  юзерспейса не существует) через платформенный сервис `IoPortOps`;
- `IRQ_ATTACH` (0x46): GSI за Irq-cap → endpoint.

**IrqRouter** (`hal/irq.rs`, GSI-keyed) — привязки линия → endpoint
(L4 irq_attach): прерывание становится signal-сообщением (word = gsi),
драйвер ждёт обычным IPC_RECV, EOI-семантика — IRQ_ACK (до ACK события
копятся одним pending-битом). Смерть задачи снимает её привязки
(detach_all_of); «горячее удаление» — не понятие ядра (менеджер
устройств в юзерспейсе отзывает caps и приказывает IRQ_DETACH).

**Фасад памяти v0.14**: одна и та же физика может стоять в НЕСКОЛЬКИХ
регионах (как frame в seL4) — ключ paddr-индекса записей — пара
(физическая база, виртуальная база); это паттерн acpi-крейта (мапит
заголовок таблицы и затем полную таблицу одного адреса, оба живы).
Снятие записи — по точной паре ключей.

**IOAPIC** (v0.11, без изменений): драйвер читает MADT (тип 1 —
override, тип 2 — базовое; ISO-флаги полярности/триггера каноничнее
подсказок флагов IRQ_ATTACH), `enable_line` программирует обычный RTE
либо remapped-формат:

- Intel VT-d: IRTE-слот 0x10+pin, remapped-RTE несёт handle+триггер
  (формат Linux IR_IO_APIC_route_entry — совместимо с QEMU);
- AMD-Vi: обычный RTE, ремап через IntTab IOAPIC-устройства,
  IRTE-индекс = вектор.

Вход по линии: свой asm-стаб на каждую линию (`VEC_EXTERNAL_BASE+pin`,
24 линии q35) кладёт GSI на стек → EOI (сразу: без переключения
контекста) → `IrqRouter` → signal в endpoint. IRQ-хендлеры соблюдают
IF-дисциплину: спины на глубине 0 — с IF=1, вложение внешних линий
ограничено одним уровнем.

**acpid** (юзерспейс, крейт `crates/acpid`): acpi::Handler поверх
MMIO_MAP (refcount-кэш перекрывающихся снапшотов) и IOP_IN/OUT;
namespace-walk (_HID/_CID/_UID/_ADR/_STA/_CRS), FADT (PM1a_EVT/CNT,
SCI), `\_S5_`; кнопка питания — SCI (GSI 9) через IRQ_ATTACH +
PWRBTN_EN; выключение ПК — IOP_OUT в PM1a_CNT значения SLP_TYPa<<10 |
SLP_EN (демо v0.14: QEMU завершается с кодом 0). AML-интерпретатор —
самая рискованная часть ACPI — теперь паникует в юзерспейсе.

**Сужение поддиапазонов (v0.15)**: деривация IoResource — решётка по
вложению: `CAP_MINT_RANGE` (0x27) выдаёт производную с диапазоном
`base..base+len`, строго вложенным в родительский той же разновидности
(инварианты: checked-вложение, len>0, совпадение вида; нарушение —
`RangeNotSubset` БЕЗ создания слота/узла дерева). CAP_MINT (0x21)
не менялся — «полный диапазон» остался ABI-совместимым путём; badge
у IoResource не применяется (гейты 0x40 его не читают). Шестой аргумент
ABI (a6 = r9) подключён впервые — asm-стаб передавал его всегда,
гейт отбрасывал (SYSCALL_ARG_COUNT 6→7; прежние сисколлы читают
arg(6)=0). Отзыв — прежний каскад дерева деривации. Демо минимальных
привилегий: init выдаёт acpid Irq 0..256 → суженный 9..10 (только SCI)
через CAP_MINT_RANGE; полный контур — CAP_MINT_RANGE →
IRQ_ATTACH(SCI 9) → PWRBTN_EN → S5.

## 10. Верификация

- **Host-тесты**: `cargo test` — ядро 136 (менеджеры, песочница,
  квоты, IPC, capability, PIE-парсер, сужение поддиапазонов ×7)
  + kernel-hal 2 (ASID-контракт, автономная сборка крейта) +
  bootcfg + boot_info; ядро гоняет их на std с host-хуками
  аллокатора.
- **Автономность контрактов (v0.15)**: `cargo build -p kernel-hal`
обязан собираться без ядра — быстрый архитектурный гейт
  («экспозиция не протекла»).
- **QEMU-прогоны** (три конфигурации: baseline / Intel VT-d
  intremap=on / AMD-Vi intremap=on, OVMF q35, TCG SMP=2): полный
  демо-сценарий init — IOMMU smoke обоих вендоров, SMP-стресс без
  lost updates, песочница (9+ атак блокированы, `sandbox HELD`),
  CPU-квота (`cpu quota HELD`, точный заряд циклами), PIE-спавн на
  двух базах, IOAPIC COM1 → L4-signal, acpid: перечисление + SCI по
  суженному гранту + S5-выключение из юзерспейса (exit 0).
- **rustfmt** — чисто на всех версиях; сборка образа — exit 0.

Регресс-политика: каждая версия проходит все три конфигурации QEMU;
счётчики планировщика (enqueue/pick/stale) сверялись при демонтаже
BKL (v0.12) и легаси-enqueue (v0.13: «sched dbg»-шум = 0 строк).
